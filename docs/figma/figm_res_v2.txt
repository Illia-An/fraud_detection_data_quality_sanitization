# Planner Layout Specification for Cursor

## Purpose

Refactor and redistribute existing application components to match the inspected desktop designs without replacing underlying state, data, validation, calculation, or persistence logic.

No canvas modifications were made.

---

### Evidence labels

- **Measured:** directly present in the design.
- **Derived:** calculated from measured dimensions or Auto Layout relationships.

### Important limitations

The designs establish desktop layout and several visibility transitions, but do not define:

- Responsive breakpoint values.
- Browser scroll ownership.
- Mobile layouts.
- Minimum or maximum widths.
- Complete behavior for every visible control.

Recommendations below are not claims about authored responsive behavior.

# 1. Shared page and grid architecture

## 1.1 Three-column application shell

**Measured:** all three states use the same horizontal, gapless shell.

| Zone | Position at reference size | Width rule | Height | Viewport width share |
|---|---:|---|---:|---:|
| Navigation | x = 0 | 176 px rendered width | 1280 px, fill parent | 9.26% |
| Planning controls | x = 176 | Fixed 320 px | Fill parent | 16.84% |
| Analytics | x = 496 | Fill remaining width: 1404 px | Fill parent | 73.89% |

### Implementation sizing contract

- Root: horizontal layout, full viewport width and height.
- Navigation: nonshrinking 176 px expanded width.
- Controls: nonshrinking 320 px width.
- Analytics: flexible remaining width, with min-width: 0.
- Formula with expanded navigation:
  - Analytics outer width = viewport width − 496 px.
  - Analytics content width = viewport width − 544 px.
- At 1900 px viewport width:
  - Analytics outer width = 1404 px.
  - Analytics content width = 1356 px.

Do not implement the measured percentages as column widths. The first two columns are stable-width regions; analytics absorbs width changes.

The navigation wrapper is technically width-to-content in the design, but its child establishes the 176 px width. Treat it as a fixed-width shell column.

## 1.2 Scroll ownership and fixed regions

### Measured

- Screen roots and the three main regions clip their contents.
- Authored overflow is NONE.
- No vertical or horizontal scrolling is configured.
- The controls footer is bottom-anchored through a flexible middle region, not an absolutely positioned overlay.
- Analytics content stacks from the top.
- No sticky analytics header is authored.

### Recommended production behavior

- Keep the application shell viewport-height.
- Prevent document-level scrolling.
- Keep navigation stationary; allow internal scrolling only if height becomes insufficient.
- Structure controls as three vertical rows:
  1. Content-height title.
  2. Flexible, independently vertically scrollable inputs.
  3. Content-height action footer.
- Use analytics as the primary vertical scroll container.
- Put wide tables inside independent horizontal overflow wrappers.
- Avoid a second vertical scrollbar inside the six-row exception preview.

This preserves access to controls on shorter displays without arbitrarily shrinking charts.

# 5. Responsive and state-transition contract

## 5.1 Behavior established by the design

| State change | Layout consequence |
|---|---|
| Expand exception list | Compact both network plots from 290 to 140 px; reveal filters and six-row table |
| Collapse exception list | Restore overview plots and summary-only disclosure |
| Open manual controls | Add 184 px section plus 24 px gap inside controls |
| Expand exports | Add 32 px row plus 8 px gap to footer |
| Hide one chart legend | Remove 16 px legend plus one 8 px gap; plot height remains unchanged |
| Open inspection | Overlay expanded page without underlying column redistribution |
| Collapse estimate evidence | Remove 270 px of dialog content |
| Collapse navigation variant | Width changes from 176 to 64 px; analytics can gain 112 px |

Additional rules:

- Legend visibility is independent for each chart.
- Hiding a legend does not hide its data series.
- Authored navigation between the three screen states is instantaneous.
- No sliding, chart morphing, or drawer animation is specified.

## 5.2 Recommended responsive constraints

These are implementation recommendations, not measured breakpoint specifications.

### Desktop width changes

- Preserve 176 px navigation and 320 px controls while content fits.
- Let analytics and chart plots resize to their container width.
- Preserve chart heights by display state.
- Do not scale the entire screen proportionally.
- Recalculate chart scales and tick density for available width.
- Reduce x-axis label density before reducing label font size.
- Allow metadata and header rows to wrap when necessary.

### Narrower layouts

- Prefer the existing 64 px navigation variant before shrinking controls.
- When a 320 px controls column leaves insufficient analytics width, expose the same controls through a dismissible overlay panel.
- This narrow-screen controls panel is an adaptation, not an authored state.
- Preserve controls state when moving between docked and overlay presentation.
- Reflow KPI cards into fewer columns when labels and values no longer fit.
- Keep charts stacked.
- Keep tables horizontally scrollable.
- Do not wrap numerical cells into multiple lines.
- Choose breakpoint values from actual minimum-content widths; the design does not establish exact breakpoint numbers.

### Shorter viewports

- Scroll the controls’ middle region.
- Keep the action footer visible.
- Scroll analytics vertically.
- Do not compress compact plots below 140 px merely to force the expanded page above the fold.

### Dialog

Recommended behavior:

- Width = available viewport width minus safe side gutters, capped at 1600 px.
- Maximum height = viewport height minus safe top/bottom gutters.
- Center within the viewport.
- If maximum height is reached, scroll the dialog body.
- Keep close controls accessible.
- Lock background scrolling.
- Trap focus inside the dialog.
- Restore focus to the invoking control on close.

Escape-key and backdrop-click dismissal are not authored; follow existing application conventions.

# 6. Alignment, typography, and spacing

## 6.1 Numerical alignment

### Measured

- Table numerical cells are visually right-aligned through parent-cell alignment.
- Some individual text layers report left alignment because they hug their contents.
- Their cell containers still place them against the right edge.
- Numerical column headers are explicitly right-aligned.
- Numeric table font:
  - IBM Plex Mono.
  - Generally 12 px size / 20 px line height.
- KPI values:
  - IBM Plex Mono.
  - Generally 20 px size / 28 px line height.
- Supporting interface text:
  - Inter.

### Implementation rules

- Right-align numerical table headers and values.
- Right-align numeric inputs.
- Use tabular numerals.
- Preserve units and signed values.
- Keep percentage points (“pp”) distinct from percentages (“%”).
- Preserve left alignment for:
  - KPI card content.
  - Store identifiers.
  - Action links.
  - Descriptive text.
- Keep numeric values on one line.
- Use shared formatting functions for consistent precision across charts, KPIs, and tables.

# 7. Cursor handoff mapping and state preservation

## 7.1 Reuse contract

The design already uses linked instances for:

- Numeric inputs.
- Question cards.
- KPIs.
- Status pills.
- Exception rows.
- Chart presentations.
- Simulation actions.
- Inspection dialog.

Map existing application components to these roles.

| Role | Presentation responsibility | Must continue using |
|---|---|---|
| Controls region | Goal, time, scenarios, manual settings | Existing form values, validation, and scenario handlers |
| Action footer | Run, save, revert, export | Existing mutation and download handlers |
| KPI strip | Current derived summaries | Existing selectors and calculation results |
| Chart presentation | Overview, compact, and store density | Existing series, scales, filters, and chart interactions |
| Exception disclosure | Open state and table visibility | Existing ranked/filterable store collection |
| Exception row | Store metrics and inspection action | Stable store identifier |
| Inspection dialog | Selected-store preview | Existing preview/draft distinction and calculations |
| Evidence disclosure | Monthly evidence visibility | Existing estimates, actuals, differences, and validation |

## 7.2 State boundaries

Keep presentation state independent from domain state.

### Presentation state

- Navigation expanded/collapsed.
- Manual section open/closed.
- Exports open/closed.
- Exceptions open/closed.
- Per-chart legend visibility.
- Inspection open/closed.
- Estimate evidence open/closed.

### Domain state

- Target.
- Horizon.
- Reference month.
- Scenario.
- Draft plan.
- Saved plan.
- Selected store.
- Estimates.
- Preview calculations.

### Do not

- Create separate planning models for overview, exceptions, and inspection.
- Re-run simulations merely because a section expands.
- Reset inputs when a panel changes position.
- Recreate chart instances unnecessarily when only plot height changes.
- Treat inspection preview as a committed draft change.
- Change ranking or calculations to reconcile visual sample values.

## 7.3 Data inconsistencies requiring clarification

The selected states contain materially different values for the same store across list and inspection.

| Context | Displayed values |
|---|---|
| Exception list | Plan As-Of 59.6%; gap −24.4 pp |
| Inspection summary | Plan As-Of 35.2%; gap 0.0 pp |
| Inspection monthly evidence | January estimate 59.6; actual 35.2; difference −24.4 |
| List and December estimate | End value 73.8% |
| Inspection summary | End value 99.4% |

The inspection context distinguishes preview from saved-draft ranking, but does not fully explain every discrepancy.

Retain existing data semantics and surface these as product/data clarification items.

Do not hardcode the displayed samples into calculations.

- Shell columns render at 176 / 320 / 1404 px.

- Overview contains:
  - Two 397 px chart cards.
  - One 52 px exception summary.

  - Two 247 px chart cards.
  - One 421 px exception section.
- Numeric table headers and values share right-aligned column edges.
- Controls retain a visible bottom action region.
- Inspection overlays the unchanged expanded layout.
- Inspection reference dimensions are 1600 × 1032 px.

- Resizing preserves form values, draft state, selection, and preview state.
